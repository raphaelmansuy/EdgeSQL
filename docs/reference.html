Reference

The public surface, the product IR, the error catalog, and the dialect rules. Public names are Query, Filter, FilterSet, Preview, AuditRecord, SqlCraftError, col, select, and param.

Parse

CallResult
Query.parse(sql, *, dialect, schema=None, mode="library")A Query, or a SqlCraftError
query.to_sql(dialect=None, pretty=False)SQL text. A parsed query keeps its dialect.
query.to_tree()The product IR document

Parse runs the gates in order and stops at the first miss: known dialect, non-empty text, one parse result, exactly one statement, a SELECT or WITH root, the dialect rules, column resolution, then the optional pglast check on Postgres.

A filter reports one conjunct. An OR group is one item. The via list records each CTE or derived table on the path to the physical table.

Builders

from edgesql import col, param, select

query = (
    select("sales.orders")
    .where(col("status").eq("paid"))
    .where(col("amount").gt(param("floor")))
    .limit(100)
)
print(query.to_sql("postgres"))    # ... amount > %(floor)s LIMIT 100
print(query.to_sql("databricks"))  # ... amount > :floor LIMIT 100

col(name) offers eq, ne, gt, gte, lt, and lte. param(name) makes a marker. select(table) starts a SELECT *. A built query has no parse dialect, so both dialects are available.

Product IR

schemaVersion is "0.1". The document has schemaVersion, dialect, rootId, and a flat nodes map. Every node has kind, children, and editable. An editable node adds editMode: "param_value".

{
  "schemaVersion": "0.1",
  "dialect": "postgres",
  "rootId": "n_select",
  "nodes": {
    "n_select": {"kind": "Select", "children": ["n_from", "n_where"], "editable": false},
    "n_from": {"kind": "From", "table": "sales.orders", "children": [], "editable": false},
    "n_where": {"kind": "Where", "children": ["n_cmp_cust_eq"], "editable": false},
    "n_cmp_cust_eq": {
      "kind": "Comparison",
      "editable": true,
      "editMode": "param_value",
      "children": [],
      "op": "=",
      "left": {"column": "cust_id"},
      "right": {"value": 42}
    }
  }
}

A comparison is editable only when its right side is a literal, a boolean, a NULL, a negative number, or a parameter marker. A comparison against a column or a function is read-only.

Errors
