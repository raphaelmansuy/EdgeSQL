Change SQL on a typed tree, not with string replacement.

EdgeSQL reads a Postgres or Databricks statement, resolves every column, and edits a copy of the syntax tree. You preview the change, then apply it. When the change cannot be safe, it stops and names the reason.

Why a typed tree

A string edit cannot tell a column name from a comment. It cannot tell which table owns a column. It breaks when two edits touch the same name. EdgeSQL keeps the parsed tree instead. A rename knows the table, the CTE hops, and the output name it must keep.

One resolver

Scope and column rules live in one module. Filters, columns, and renames all read the same answer.

postgres and databricks

Preview before commit

Preview returns the before SQL, the after SQL, an AST diff, a semantic diff, and a fingerprint. Apply refuses a blocked preview.

no silent change

Fail closed

Every error has a phase, a code, and a hint. The library emits no SQL when it cannot explain the statement.

Dynamic filter screen

The report helper builds its filter panel from the product IR. Every editable node becomes a control: number, text, range, list, or limit.

works for any query

Install and the flow

pip install edgesql    # or: uv add edgesql
python -c "import edgesql, importlib.metadata as m; print(m.version('edgesql'))"
from edgesql import Query

query = Query.parse(
    "SELECT cust_id, status FROM sales.orders",
    dialect="postgres",
)

preview = query.preview(
    lambda item: item.rename_column("cust_id", "customer_id", table="sales.orders")
)

if not preview.blocked:
    applied = preview.apply(actor="builder")
    print(applied.to_sql())
    # SELECT customer_id AS cust_id, status FROM sales.orders

The original query does not change. The rename keeps the output name cust_id, so a report that reads that column still works.

The filter screen

The example app reads the product IR and builds one row per predicate. A literal value gets a typed control. A predicate that compares two columns, or compares against a function, becomes a read-only row, because a value patch would change the meaning.
